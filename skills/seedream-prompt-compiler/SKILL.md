# Seedream 提示词编译器

职责：把**原始提示词**编译成 **编译后提示词 + 参数 + 变更 diff**，再交给 `volcengine-seedream` 出图。

> 这是**规则变换，不是扩写**。核心原则 **保真优先、默认不补全、绝不臆造、透明可回退**。
> **实测（n=39）结论：模型自身的补全/联想能力往往强于我们硬加的词——所以默认“能不动就不动”，主动补全需用户明确要求。**

## 输入 / 输出

- 输入：原始提示词；目标模型（`pro`/`flash`/`lite`/`4.0`）；可选 比例/分辨率。
- 输出（**必须全部给出**）：
  1. 编译后提示词
  2. 抽取出的参数（`-a/-s/-m/--prompt-mode` 等）
  3. 变更记录 diff（逐条：删除 / 抽取 / 归一 / 补全 / 保留）
  4. 长度（汉字数，须 ≤300）

## 规则（按顺序执行）

- **R1 剥离元指令**：删掉“帮我生成图片 / 图片风格为 / 请画”等**指令性**文字；把“比例 16:9”抽成 `-a 16:9`，分辨率抽成 `-s`。
- **R2 锁死不变量**：主体、数量、服装、表情、姿态、颜色、专有名词——**原样保留，禁止改写、增删**。
- **R3 归一化**：官方**无 `negative_prompt` 字段、不支持负向标签**；把“否定 / 排除”改写成**连贯的自然语言指令**（如“去掉帽子”），**不要**堆“不要 / 没有 XXX”的标签；合并重复表述。
- **R3.5 自然语言优先**：官方明确**不推荐关键词 / 短语堆叠**（指南以“一个女孩，撑伞，林荫街道，油画般笔触”为反例），推荐**简洁连贯的自然语言**：“主体 + 行为 + 环境”，再加 风格 / 色彩 / 光影 / 构图。**也不要使用 SD 式权重语法**（如 `(word:1.3)`、括号加权）——官方不支持。
- **R4 补全（默认关闭）**：**默认不补全**——实测中主动补“构图/光线/风格”多为噪声，不补更好。仅当**用户明确要求**“更可控 / 商业级 / 更具体”且提示词确实单薄时，才对“构图 / 光线 / 风格”各补**一个短句**（够用即止）。**绝不补背景 / 场景 / 道具**，除非用户自己提到。
- **R4.5 易错项（手 / 肢体 / 文字）**：官方**不支持负向提示词**，**禁止**写“不要画错手指 / 不要多腿”这类否定强调（无效且占长度）。改用：① **正向具体化**——直接写清肢体位置/状态（“双手自然交叠放在身前”“双腿并拢”）；② **规避**——用景别或遮挡减少易错部位（“半身特写”“双手插兜/藏在背后”“侧身”），同时保留“中景全身”保证四肢完整入画。若仍频繁出错，视为**抽样问题**：改换 `--seed` / 切 `pro` / 用编辑，**不要靠加重提示词**。
- **R4.6 换背景 / 场景编辑的空间一致性（重点）**：换背景时，**主体的"地面接触 / 姿态"必须与新环境自洽**，二选一、不许含糊：
  - **(a) 保姿态**：保留原姿态（如“仍坐在地上”），并把新背景选为**与之相容**的环境（地板 / 地毯 / 榻榻米 / 看台），且在提示词里**写明所在平面**（“坐在教室木地板上”）。
  - **(b) 改姿态**：明确要求重设姿态（“让她坐在教室课椅上、双手放在桌上”），并**接受主体会被重绘**（身份 / 细节会漂移）。
  > 只写“把背景换成教室”而不交代 姿态 × 环境 的关系 → 会出现“地上的坐姿 + 椅子”的诡异结果。**“只换背景”与“让姿态适配新环境”是冲突要求，必须指定以哪个为准。**
- **R4.7 越界添料（可控性 vs 创意）**：模型常**自行添加**未要求的元素（文字 / 图案 / 道具 / 背景）。
  - 要**创意 / 惊喜** → 不约束，甚至故意留白。
  - 要**稳定复现 / 可控** → 用**正向边界**收口：“画面中只有她一人，服装纯色、无文字与图案，背景简洁”。
  - 加边界会**牺牲丰富度**，二者是取舍；**默认不加满**，仅在用户要求可控时才收口。
- **R4.8 别把“交代清楚”直译成“画清楚 / 画细节”（实测教训 · 重点）**：用户说“把 X 交代清楚 / 说清楚 / 别漏 / 看清”，通常是**沟通诉求**（要你**确保正确表现、不遗漏**），**不是**“往画面里加‘清晰 / 细节 / 特写 / 高精度’这类词”。
  - 加这类词**可能改变画面结构**：实测把“脚部交代清楚”译成“脚趾画清楚”，结果**女孩丢了袜子**（“脚趾清晰”被模型理解成去掉遮挡）。
  - 正确处理：**不直译**——要么**原样保留**该主体的既有描述，要么把它带到 **Ask Gate** 里**回问**用户“你要的是‘确保脚部露出 / 不被遮挡’，还是‘加脚部特写’？”由用户定。
  - 同类警惕：“更真实 / 更清晰 / 更有质感 / 画面更丰富”等**模糊品质词**：多为噪声，且可能触发越界添料（见 R4、R4.7）。
- **R5 长度闸门**：≤300 汉字；超出时按优先级裁剪：装饰性形容词 → 冗余限定 → 重复；**绝不删 R2 的锁定项**。
- **R5.5 长度由"控制维度"决定，不是越长越好**：
  - **简洁模式（默认）**：用户只想"随手出图 / 要创意"→ 保留 主体 + 行为 + 环境（约 30–60 字），留白给模型，多样性更高。
  - **可控模式（要精确 / 商业级）**：按"控制清单"补齐用户**在意**的维度，每维一个短语，仍 ≤300 字、**零填充词**：
    主体/行为 · 环境 · 构图/景别/视角 · 光线 · 风格 · 色彩 · 质感 · 镜头或器材（如 `35mm`）/胶片。
    > 官方长样例正是"逐维控制"的商业写法（人物+服装+道具+构图+光线+风格+器材+胶片+景深+色调+质感）。
  - **禁填充**：`8k / 超清 / masterpiece / 杰作` 等**无信息量**的词一律删——清晰度由 `-s` 控制，不由文字。
  - **"长"分两种**：连贯自然语言的长（好）vs 关键词堆叠的长（官方反对，见 R3.5）。
- **R6 模型门控**（只改默认值与能力，**不改措辞**）：
  - `flash`：默认 `-s 1.5K`；提示词保持**精简**（未证其明显更差，先试 flash）。
  - `pro`：可 `-s 2K`；**仅 pro** 支持 `--prompt-mode fast` 与交互编辑 / 图层拆分。
  - `lite`：**唯一**支持 `--web-search`；最高 4K。
  - `4.0`：可 4K 输出（`-s 4K`）。
  - **选型策略（能力驱动 + 失败驱动升级，而非“复杂度”猜测）**：
    - 默认 `flash`。**能力硬需求**直接上 `pro`：精确/交互编辑、图层拆分、需高保真（保身份/细节）的成片。
    - 否则先 flash 抽 1–2 张：**结构类失败**（姿态/肢体/构图/多主体混乱，重抽仍不对）→ **升级 pro**；仅**审美不讨喜** → 继续 flash 重抽或接受，**别升级**。
    - 依据是“失败类型”，不是“我觉得这题难”。成本判据：flash 更划算 ⟺ `p_pro / p_flash < 2.5`（1.5K；2K 则要 <5）。
- **R7 透明**：输出 diff，用户一句话即可否决。

## 硬禁止

- 禁止臆造用户没给的背景 / 场景 / 道具。
- 禁止改写 R2 锁定项（**姿态尤其**——实测中改写姿态曾导致“四条腿”崩坏）。
- 禁止为“好看”堆砌超过必要的风格词。
- 禁止超过 300 汉字。
- 禁止关键词 / 短语堆叠；禁止 SD 式权重语法（`(word:1.3)`）。
- 需要画面内出现文字时：**建议**把文字内容用双引号包裹（官方建议）；但**实测主体文字（海报/招牌）即便不加引号也常能正确渲染**，双引号非必需。**微小道具文字（如书封面）仍不可靠。**
- 禁止把“编译”做成“扩写”。

## 示例

### 例 1：已具体 → 默认几乎不动
原始：`动漫风格，一个穿浅蓝色连帽卫衣和运动短裤的女生，戴着金色圆边眼镜，微笑，wink，扎低马尾辫子，趴着双腿翘起，比例16:9`

编译后：`动漫插画风格，一位女生穿着浅蓝色连帽卫衣和运动短裤，戴着金色圆边眼镜，微笑并单眼眨眼(wink)，扎低马尾辫子，趴卧着、双腿向后翘起。`

- 参数：`-a 16:9 -m flash -s 1.5K`
- diff：① 删除“比例16:9”→ 抽成参数；② 短语串 → 连贯句；③ **未补任何美学要素**（默认不补全）；④ 锁定项语义原样保留。

### 例 2：模糊 → 才适合补全
原始：`画一只猫`

编译后：`一只猫，端坐正视镜头的中景，柔和自然光，浅景深背景虚化，写实摄影风格。`

- 参数：`-m flash -s 1.5K`
- diff：① 删“画”；② 补 构图 / 光线 / 风格（安全类别）；③ **不补**具体品相 / 背景。

### 反例（禁止）
原始：`动漫女生趴着翘腿`
错误编译：`……趴在铺着浅色地毯的房间里，阳光从落地窗照入……` ← **臆造了背景 / 场景，禁止**。

## 官方要点（《Seedream 4.0-5.0 提示词指南》直证）

- 用**简洁连贯的自然语言**：主体 + 行为 + 环境；有美学需求再补 风格 / 色彩 / 光影 / 构图。
- 正例：“一个穿着华丽服装的女孩，撑着遮阳伞走在林荫道上，莫奈油画风格。”
- 反例（避免）：“一个女孩，撑伞，林荫街道，油画般细腻笔触。”（**关键词堆叠被官方点名**）
- **无 `negative_prompt`**；“去除 / 删除 / 替换”用自然语言写成指令（图像编辑示例：“去掉女生的帽子”）。
- **画面内文字**：把要渲染的文字放进**双引号**（正例：标题为“Seedream 4.5”）。
- **无权重语法**：`(word:1.3)`、括号加权等**不支持**。
- 长度上限：**≤300 汉字 / 600 英文单词**。
- 独立官方指南：https://docs.volcengine.com/docs/ark/seedream-4-0-5-0-prompt-guide

## 验证结果（2026-10，n=39 正式实验）

5 场景（单主体 / 单主体精确 / 多主体复杂 / 含文字 / 参考图编辑）× {raw, compiled} × {flash, pro} 盲评：

- **编译器整体未带来增益，甚至略负**：flash `raw` 审美 **4.50** vs `compiled` **4.33**；通过 **15/15 vs 14/15**。**逐场景 compiled 从未胜过 raw**。
- 早先“编译 2/2 胜”（n=2）**未被复制**，判定为**噪声**。
- **结论**：“已具体 / 已清楚”的提示词，主动补的构图 / 光线 / 风格词 ≈ **噪声，不加更好**。
- **编译器仍有效的部分**：剥元指令、抽参数、自然语言化、双引号、长度闸门、R4.6 空间一致性。
- **模型自身补全**常自行添加背景 / 光影 / 配饰（有时加分、有时越界）——见 R4.7。

## 编译前检查清单（Pre-flight）

出图前逐项确认，命中易错项就按对应规则处理：

- [ ] **姿态 × 环境**是否自洽？（换背景/场景 → R4.6：保姿态选相容环境，或明确改姿态）
- [ ] **肢体/手**是否易崩？→ R4.5：正向写清 + 遮挡/景别规避，**别写"不要…"**
- [ ] **画面内文字**是否必需？→ 用双引号；并知悉精细文字仍可能乱码（必要时重新生成）
- [ ] **默认不补全**？只有用户要求“可控 / 商业级”时才补 构图/光线/风格（见 R4）。
- [ ] **长度**与控制需求匹配？（简洁 30–60 字 / 可控按清单，≤300，**零填充**）
- [ ] **模型**选对？（默认 `flash`；精确编辑 / 图层 / 结构精度硬要求→`pro`；4K→`4.0`；联网→`lite`）
- [ ] **分辨率**默认 1.5K（1K 同价更差）；需高清才 2K。
- [ ] **该不该多抽几张**（`-n`）而非死磕单张？

## 🚦 出图前确认闸门（Ask Gate · 必做）

> **为什么**：清理器给的提示词**仍然是“AI 写的”**，可能把模糊诉求直译成画面词、掺入你没说的东西、或改变结构（实测：把“脚部交代清楚”译成“脚趾画清楚”→ 女孩丢了袜子）。生成是**付费**操作，**出图才发现跑偏就白花钱**。所以**真正出图前**必须把成品提示词交用户拍板。

**时机**：编译 / 清理完成 → **调用 `generate_image.py` 之前**。

**动作**：用平台的提问工具（opencode 用 `question`）把以下内容**一次亮给用户**，**不要只发一段文字就自己接着出图**：

1. **编译后提示词**（完整原样）
2. **一句话 diff**：删了什么 / 抽成了哪些参数 / **有没有补全**（默认应显示“未补全”）
3. **风险标注**：凡是**超出用户原话**的词、或把模糊诉求直译成的画面词（“清晰 / 细节 / 特写 / …”），**逐条标出并说明可能的副作用**
4. **问题**：这个提示词过不过关？不过关要怎么改？

**给 `question` 的选项（三选一）**：

- `✅ 通过，出图` → 按当前提示词 + 默认参数生成
- `✏️ 我要改` → 用户给意见 → 改完**重新走本闸门**（再次确认）
- `⏭️ 本次别问，直接出` → **仅本次**跳过

**回退规则**：用户给了修改意见 → 应用修改 → **重新展示、再确认**。**未获“通过”不得调用生成脚本。**

**何时可跳过**：**只有用户显式**说“直接出图 / 不用问 / 别确认”（或本次已授权批处理）才跳过，且仅对**本次**有效。
**永远默认开启——不要自行判断“这次很简单就不用问”。**

## 与出图 skill 的衔接

编译完成后，把结果作为 `-p` 传给 `volcengine-seedream` 的 `scripts/generate_image.py`，参数按 R6 设置。
**务必先过 Ask Gate**：先展示「提示词 + diff + 风险」，**用户认可后才真正生成**（生成是付费操作）。
